# AGENTS.md

This file provides guidance to AI coding agents (and other automated tools) working in this repository.

## Project Overview

`scari` (Shifting Climate Assessment of Risk from Invasives) is an R package and research compendium that documents a multiscale, ensemble species distribution modeling (SDM) workflow. It forecasts establishment and impact risk of a species invasion as it shifts with climate change. The focal example species used throughout the vignettes is *Lycorma delicatula* (spotted lanternfly / SLF), assessed for risk to global viticulture regions, but the workflow is designed to generalize to other invasive species.

See the companion paper for the conceptual background:
Owens, S. M. (2024). *Multi-scale Modeling of the Spotted Lanternfly Lycorma delicatula (Hemiptera: Fulgoridae) Reveals Displaced Risk to Viticulture and Regional Range Expansion Due to Climate Change* [M.S., Temple University].

## Repository Structure

- `R/` — Core package functions. Includes `(0)_README_R.txt`, a manually maintained changelog describing each function and its version history. **Update this file when modifying a function's behavior.**
- `vignettes/` — Numbered pipeline steps (e.g., `010_initialize_pkg.Rmd` through `160_generate_format_figures.Rmd`). Vignettes are ordered and often depend on outputs from earlier ones (see the sitemap in `README.md`). Includes `000_README_vignettes.txt` describing each vignette.
- `data-raw/` — Raw input data and data-preparation scripts. Includes `(0)_README_data_raw.txt`, which follows the same changelog convention as `R/`.
- `man/`, `NAMESPACE` — Generated by `roxygen2`. **Do not hand-edit.** Regenerate with `devtools::document()`.
- `docs/`, `pkgdown/`, `_pkgdown.yml` — Generated `pkgdown` site output. **Do not hand-edit `docs/`.**
- `renv/`, `renv.lock` — Dependency lockfile managed by `renv`. Do not alter pinned package versions without an explicit reason tied to the task.
- `DESCRIPTION` — Package metadata, dependencies, and license declaration.
- `LICENSE`, `LICENSE.md` — MIT license (short form + full text).

## Coding Conventions

- Follow the existing R style already used in `R/` (roxygen2 doc comments above each function, tidyverse-style piping and naming).
- **Changelog convention:** when you modify a function in `R/`, add a new version entry (e.g., `v8- YYYY-MM-DD- description of change`) to the corresponding section in `R/(0)_README_R.txt`. The same convention applies to `data-raw/(0)_README_data_raw.txt` for changes there.
- **`_CV` naming convention:** functions suffixed with `_CV` (e.g., `predict_xy_suitability_CV.R`) operate on cross-validated `SDModelCV` S4 objects from `SDMtune`. Functions without the suffix (e.g., `predict_xy_suitability.R`) operate on single `Maxent` S4 objects. These are parallel, intentionally separate implementations — do not merge or collapse them without explicit instruction.
- Preserve the numbered vignette convention (e.g., `NNN_description.Rmd`) if adding a new pipeline stage, and place it in the correct sequence position.

## Build / Validation

- Environment setup: run `renv::restore()` to install pinned dependency versions before making changes.
- To validate function changes: use `devtools::load_all()` and `devtools::document()` (to regenerate `man/`/`NAMESPACE` from roxygen comments) rather than editing generated files directly.
- `devtools::check()` can be used for a fuller package check when appropriate.
- Vignettes are long-running, require Java (`rJava`) for MaxEnt modeling via `SDMtune`/`dismo`, and depend on large external datasets (climate rasters, occurrence records). **Do not attempt to fully re-render vignettes as a validation step** — this is computationally expensive and not a reasonable check for most changes. Prefer syntax/lint-level validation of `.Rmd` code chunks instead.

## Dependencies

- Requires a working Java installation for `rJava` (used by `dismo`/`SDMtune` for MaxEnt).
- Several dependencies are installed from GitHub rather than CRAN, some pinned to specific versions/commits (see `Remotes:` in `DESCRIPTION`, e.g. `ieco-lab/lydemapr`, pinned `ggnewscale`, `GeoThinneR`, `tidygeocoder`). Do not change these pins unless the task explicitly requires it.
